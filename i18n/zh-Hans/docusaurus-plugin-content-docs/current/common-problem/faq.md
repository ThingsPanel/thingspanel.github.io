# 常见问题

## ThingsPanel 是基于 ThingsBoard 开发的吗？

不是。ThingsPanel 不是基于 ThingsBoard 开发，也不依赖 ThingsBoard 运行。ThingsPanel 采用独立的插件化设备接入架构，平台功能、设备接入服务和可视化应用均由 ThingsPanel 自身维护。

## ThingsPanel 对服务器配置有什么要求？

最低配置为 **1 核 CPU、1 GB 内存、10 GB 硬盘**，适合功能体验、开发测试和少量设备接入。

生产环境建议使用 **4 核 CPU、8 GB 内存、100 GB 硬盘**。实际可承载的设备数量还会受到设备上报频率、数据保存周期、插件数量、数据库和磁盘 I/O 等因素影响，正式项目建议根据实际数据量压测并预留资源。

常见的 CPU 通常都可以支持，包括 x86/AMD64 和 ARM 等架构；具体以所选择的安装方式和操作系统支持情况为准。

## ThingsPanel 支持 APP 吗？

支持。ThingsPanel 提供 Web 端和移动端应用，移动端支持 Android 和 iOS。需要小程序或 H5 时，也可以基于移动端源码自行部署和发布。

可参考[演示平台与移动端说明](../introduction/demo)。

## 社区版本可以免费商用吗？

可以。ThingsPanel 社区版本可以免费用于商业项目，核心代码采用 Apache 2.0 开源许可。使用时请遵守 Apache 2.0 许可证中的版权声明、许可证通知等要求；项目中集成的第三方组件或服务，还需要遵守其各自的许可证和服务条款。

## ThingsPanel 支持哪些操作系统和部署方式？

支持 Linux、Windows 和 macOS 等常见操作系统，也支持 Docker、一键安装脚本、源码安装等方式；对于有高可用和高并发需求的项目，可以进一步采用集群部署。

建议首次部署参考[快速部署指南](../quick_start/quick_start.md)，生产环境部署前先确认 Docker、网络端口、磁盘空间和数据备份方案。

## ThingsPanel 支持哪些设备和通信协议？

ThingsPanel 支持多种设备类型和接入方式，包括直连设备、网关和子设备。常见协议包括 MQTT、HTTP、TCP、Modbus RTU/TCP、OPC UA、GB28181，以及水文、电力、报警等行业协议；同时支持部分第三方平台接入。

如果现有设备使用私有协议，也可以通过设备接入服务或自定义协议进行扩展。具体可参考[设备接入概览](../device-connectivity/overview)。

## 接入设备必须使用 SDK 吗？

不必须。设备可以按照 ThingsPanel 支持的通信协议直接接入，也可以使用 MQTT、HTTP 等标准客户端；如果协议不在现有支持范围内，可以开发自定义设备接入服务，不需要修改平台核心业务。

## 可以批量添加设备吗？

可以。ThingsPanel 支持手动添加、批量导入、按设备 ID 添加，以及通过第三方平台批量接入。批量导入适合一次性初始化较多设备，按 ID 添加适合设备预注册后通过扫码或设备自身信息完成绑定。

## ThingsPanel 支持设备远程控制、告警和 OTA 升级吗？

支持。平台可以查看设备实时数据和历史数据，并通过设备协议进行属性下发或命令控制；同时支持告警规则、通知配置和 MQTT 设备 OTA 升级。具体能力取决于设备协议和设备端固件的配合。

## 可以和已有业务系统或第三方平台集成吗？

可以。ThingsPanel 提供 API 和设备接入服务，可用于设备管理、数据查询、实时数据订阅和业务系统集成；也支持通过第三方接入服务同步设备数据。集成前请根据目标系统确认鉴权方式、数据格式和接口权限。

## 如何选择部署配置和设备数量？

不要只按设备总数估算。相同数量的设备，如果上报频率、单次消息大小、历史数据保存周期不同，对 CPU、内存、数据库和磁盘 I/O 的压力可能差异很大。

建议先用最低配置完成验证，再按“设备数量 × 上报频率 × 单次数据量 × 保存周期”评估生产资源；设备规模、数据吞吐或可用性要求较高时，建议使用推荐配置并进行压测或采用集群部署。

## 升级 ThingsPanel 前需要注意什么？

升级前建议备份数据库、配置文件、自定义插件和扩展，并确认新旧版本的兼容性。不同版本之间不一定支持直接升级，尤其是跨较大版本时，应先阅读对应的升级说明并在测试环境验证，再安排生产升级。

可参考[系统升级指南](../installation/system_upgrade)。
