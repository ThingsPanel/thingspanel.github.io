# 通知策略

通知策略用于选择超管配置的服务、通知目标和告警内容。页面暂时保留原路由 `/alarm/notification-group`，用户界面名称为“通知策略”。

```mermaid
flowchart LR
  Admin[超管分配服务] --> Tenant[租户查看可用服务]
  Tenant --> Strategy[选择服务、目标和内容]
  Strategy --> Alarm[在告警规则中选择策略]
  Alarm --> Record[查看新投递或旧历史]
```

## 1. 创建通知策略

1. 打开**告警 → 通知策略**。
2. 查看当前租户可用服务。列表只显示由系统超管配置并分配的服务；租户界面不会显示服务商密钥。

![租户查看可用通知服务](/img/notification/tenant-services-readonly.jpg)

*开发环境截图。图中的 SMTP 实例已停用；图片仅展示只读服务列表，不表示该账号当前可发送。*

3. 点击“新建通知策略”，填写策略信息、通知目标和所选服务支持的消息内容。
4. 保存后重新打开策略，核对保存结果。保存或校验策略不会发送通知。
5. 打开告警规则，选择需要使用该策略的规则。

只有显式选择该策略的告警规则才会使用它。创建策略不会自动应用到所有告警，也不表示系统已有全局继承默认策略。

## 2. 仅在需要时测试发送

测试发送会真实提交给服务商。确认前检查收件目标、消息内容和可能产生的费用。保存或配置校验不会发送通知。

| 状态 | 含义 |
|---|---|
| 已排队 | 通知意图已可靠写入队列。 |
| 服务商已受理 | 服务商接受了请求；尚未确认送达。 |
| 已送达 / 送达失败 | 可信的服务商回执报告了最终状态。 |
| 结果未知 | 无法确认服务商处理结果，不要盲目重复发送。 |
| 已受理但无回执 | 服务商已受理，但该渠道不提供送达回执。 |

## 3. 查看通知记录

打开**告警 → 通知记录**。新投递与旧历史分别显示。旧记录中的 `SUCCESS` 或 `FAILURE` 表示旧系统状态，不是收件人实际收到消息的证明。

## 4. 旧通知组

旧通知组维护页签已移除，不再支持新增、编辑或删除旧通知组。旧组列表和详情仍可只读查看以兼容历史来源，原有历史数据保留。不要通过旧组的编辑流程配置新策略。

## 5. 租户权限

社区版没有租户子用户或租户角色管理流程。可用服务和记录由当前租户会话决定。如果缺少所需服务，请联系系统超管；不要在租户表单中输入服务商密钥。

服务商集成源码和插件契约见[插件开发指南](../../../developer-guide/notification-plugin.md)。
